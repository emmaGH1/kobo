Only the head can be answered, each answer creates a replacement review (new ID), and the reply says how many questions remain. Legacy pending reviews without per-entry amount metadata are no longer answerable conversationally (they expire in 30 minutes anyway).

## Implemented
- `src/server/service.ts`: channel-neutral message/review/confirm/edit/cancel, validated model tool calls, deterministic owner-scoped balances/debtors/daily summary, and source-checked extraction. Natural-language entries can be reviewed and explicitly confirmed; the model's interpretation of the quoted words is not independently verified. Purchases additionally accept `stock purchase: DESCRIPTION: AMOUNT` deterministically. Amounts are naira converted to integer kobo.
- Web auth/route (`src/server/web.ts`, `src/app/api/dev/route.ts`): separate new fictional demo tenant per login, owner passcode from `OWNER_PASSCODE` (minimum 12 characters; not configured in the current local environment), hashed opaque server-side sessions, HttpOnly/SameSite cookies (Secure in production), explicit Origin check, persistent throttles and owner-scoped access. `/dev` is intentionally bare. Production requires HTTPS and a proxy preserving the external Host; local HTTP is allowed only outside production. Logout revokes the session. Login uses a global throttle; demo and model usage have global rate caps, but there is no billing budget or full abuse-prevention system.
- Credit sales may include an explicitly stated `YYYY-MM-DD`, today or tomorrow due date, validated and persisted. Stock purchases append a separate immutable purchase event, and Lagos daily summary includes stock spent. Purchases record a description and total cost, not quantities/inventory valuation; purchase correction/reversal is not implemented. Reminder drafts use a caller-supplied international-digit number and an owner-checked positive balance, returning a `wa.me` link; no message is sent. Due dates are not used to allocate partial payments or determine overdue status.
- SQLite records only numeric token counts/timestamps for valid provider usage. No prompt, response, credential or customer details are written to application logs. Private pending/evidence storage does contain transaction input by design. Existing databases are migrated to add `due_date` at store initialization; back up before using any persistent data.

## Remaining safety / follow-up
Natural-language reviews now depend on model semantic interpretation, despite literal source checks and explicit user confirmation. Prompt injection and misclassification remain safety risks; real-world acceptance requires independent semantic safeguards, a fuller clarification protocol and broader adversarial tests. There is no audio, webhook authentication, reminder scheduling, purchase reversal, inventory quantity, due-date settlement allocation, owner passcode recovery/rotation flow, session administration, real backup/restore or deployment hardening. Demo tenants/sessions have no retention cleanup; global in-database throttling can be used for denial-of-service and does not bound total spend. Secure cookies/Origin behavior and proxy Host configuration need real HTTPS verification. Current owner passcode is unset; configure it privately before owner login, never commit it. Independent security review, backup/recovery testing, abuse/cost controls and migration testing are required before actual trader data or public exposure.
